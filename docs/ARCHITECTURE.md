# 本地项目演进

目标平台：Windows。当前阶段只做 IGDB 全年资料采集，所有代码纳入当前 Git 仓库。

资料库只有一个用户入口，以 IGDB 游戏记录为基础，评分是游戏详情中的关联内容。
当前以 igdb_id 为游戏键；IGN 评测以后通过明确的匹配记录关联到游戏，不建立第二个用户功能。
以后依次加入：
1. 本地分类字段与筛选查询（当前已实现），再接 FastAPI 查询。
2. IGN 评分来源适配与 IGDB/IGN 身份匹配。
3. Vue 3 本地网页与 Windows 桌面入口。
4. Steam 账号绑定、时长与成就同步。
5. 用户偏好、个人记录与 AI 推荐。

IGDB rating 与 IGN score 必须按来源分别保存。
一个游戏可关联多篇 IGN 评测，保留各篇评测的评分、评测对象（整体/战役/多人等）、标题、日期和 URL。
不按同名自动合并、不自动取最高分或平均分。候选匹配可以按名称和平台提出，再人工确认。
尚无 IGN 关联时详情页不展示 IGN 区块；有多个关联时逐篇展示。以后“有 IGN 评测”可以成为筛选项。
采集原始来源事实、人工修正和个人记录分别维护。
当前SQLite schema_versions记录结构版本；后续改变结构必须提供迁移，不通过删库升级。

代码放src，测试放tests，文档放docs。凭据、采集数据库与导出文件不进入Git。
OpenClaw后续通过明确的任务和查询接口监督；当前命令行采集不依赖它。

分类字段和展示规则见 CLASSIFICATION.md。数据库表分工是实现细节，不对应多个资料库功能。
