# 游戏平台 → 玩法类型：回流、开口与下落

本次只实现这一段过渡。现有菱形基座、科技树的轮廓、配色、分支布局、模块、拖动缩放和常态样式保持原样。年份与平台、玩法类型与游玩模式继续采用原有过渡。

## 动作顺序

1. 有挂载分支时，从现有分支的末端发出亮光，沿实际叶节点连线和主干汇入核心。画面和树结构保持稳定，不再把科技树缩成一团。是否发光依据实际挂载情况，不依据是否勾选某个平台。
2. 回流完成后，基座原有表面中央逐渐展开菱形缺口，保留原轮廓和原有环线。开口采用临时遮罩；常态时不应用遮罩、不增加可见装饰。
3. 开口期间基座、光球、页面与背景保持原位。开口完成即开始释放，没有额外停顿；光球开始下落后镜头才跟随，平台页和背景连续向上移动。光球相对基座始终向下运动，穿过基座底部后才开始横向靠近星图中心。
4. 平台页继续上移，背景星空沿用已有视差和补充机制；玩法类型的文字从下方进入。核心抵达原有星图中心后，才用现有方式展开星座。
5. 反向滚动严格还原同一组进度函数，回到平台页后关闭缺口并恢复常态。滚轮停在中间不会自动播放剩余动作。

没有挂载分支时跳过回流，提前展开缺口；星图仍在核心落位后展开。

## 几何与状态

- 光流直接采样现有 `trunkPath`、`twigPath` 和其他平台细分类的 `clusterPath`，不绘制新的永久连接线。每个品牌最多 3 条光流，已展开的其他平台详情最多再补充 2 条，整体最多 20 条。
- 过渡不会重建分支，不更改分支朝向、勾选状态或筛选草稿；搜索、收起分支、其他平台分页仍保留原行为。
- 光球拖尾依据真实下落轨迹计算，正向在运动后方，反向也随之翻转。开口静止期间不添加飞行拖尾。
- 视口变化后重新测量原有锚点和缩放。拖动、缩放后从当前基座出发。
- 系统减少动态效果时直接到达完整页面，不播放光流或中间过渡。关闭与取消会沿用现有草稿清理流程。
- 不增加数据请求，不修改后端或数据库，没有新增依赖。

## 遮挡与洞口

- 共享光球按原基座的 SVG 实体轮廓和动态洞口裁切，依次部分遮挡、完全遮挡、从底部露出，不用整体透明度模拟穿孔。
- 平台标签同样作为前景遮挡，按实际位置、圆角、缩放与视口裁切测量。过渡期间缓存布局，避免逐帧读取全部标签。
- 洞口内的科技树连线和光流同步裁掉，洞外连接保留；返回平台页后撤销临时裁切。
- `platform-occlusion.test.mjs` 检查多种缩放的穿孔遮挡、标签圆角与裁切、开口静止、下落同步跟随、反向和洞口坐标。

## 验证

`frontend/tests/platform-genre-transit.test.mjs` 覆盖回流与开口的先后、空基座、常态树缩放、开口静止与镜头跟随、不同窗口和缩放下的向下释放、穿孔后横向转弯、落位后展开、正反向连续性、拖尾及有限光流池。

浏览器检查包括原版与新版的常态截图对比、挂载与空基座、实际连线上的光流、原菱形开口、共享核心与插槽对齐、暂停和反向、其他平台的细分类、确认/取消、窄窗口、减少动态效果与其他筛选页。
